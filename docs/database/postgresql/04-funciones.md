# PostgreSQL — Funciones y triggers

## Función SQL

```sql
CREATE OR REPLACE FUNCTION count_open_tasks()
RETURNS bigint
LANGUAGE sql
STABLE
AS $$
    SELECT COUNT(*) FROM tasks WHERE status <> 'done';
$$;

SELECT count_open_tasks();
```

## Función con argumento

```sql
CREATE OR REPLACE FUNCTION tasks_by_status(p_status text)
RETURNS SETOF tasks
LANGUAGE sql
STABLE
AS $$
    SELECT * FROM tasks WHERE status = p_status ORDER BY created_at DESC;
$$;

SELECT * FROM tasks_by_status('pending');
```

## Trigger: impedir un estado desconocido (además del CHECK)

El `CHECK` suele bastar. Un trigger merece la pena cuando la regla usa otras filas.

Ejemplo: registrar cada cambio de estado.

```sql
CREATE TABLE task_status_log (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    task_id bigint NOT NULL,
    old_status varchar(20),
    new_status varchar(20) NOT NULL,
    changed_at timestamptz NOT NULL DEFAULT now()
);

CREATE OR REPLACE FUNCTION log_task_status()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
    IF TG_OP = 'UPDATE' AND NEW.status IS DISTINCT FROM OLD.status THEN
        INSERT INTO task_status_log (task_id, old_status, new_status)
        VALUES (NEW.id, OLD.status, NEW.status);
    END IF;
    RETURN NEW;
END;
$$;

CREATE TRIGGER trg_log_task_status
AFTER UPDATE OF status ON tasks
FOR EACH ROW
EXECUTE FUNCTION log_task_status();
```

En PostgreSQL 11+ el trigger llama `EXECUTE FUNCTION` (también se acepta `EXECUTE PROCEDURE` en versiones viejas).

## updated_at automático

```sql
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
    NEW.updated_at = now();
    RETURN NEW;
END;
$$;
```

El trigger tiene que ser `BEFORE UPDATE`, porque modifica `NEW`.

## Transacción en un bloque

```sql
BEGIN;
INSERT INTO tasks (title) VALUES ('Una');
INSERT INTO tasks (title) VALUES ('Otra');
COMMIT;
```

Si la segunda falla y no hay `COMMIT`, haz `ROLLBACK`.

## Vista

```sql
CREATE OR REPLACE VIEW open_tasks AS
SELECT id, title, status, created_at
FROM tasks
WHERE status <> 'done';
```

Una vista no guarda datos. Sirve para no repetir el `SELECT` en el enunciado.
