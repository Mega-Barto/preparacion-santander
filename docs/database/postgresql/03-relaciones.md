# PostgreSQL — Relaciones, claves e índices

## Tabla con PK y FK

```sql
CREATE TABLE users (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    email varchar(180) NOT NULL UNIQUE,
    name varchar(120) NOT NULL
);

CREATE TABLE tasks (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title varchar(180) NOT NULL,
    description text,
    status varchar(20) NOT NULL DEFAULT 'pending',
    created_at timestamptz NOT NULL DEFAULT now(),
    owner_id bigint NOT NULL REFERENCES users (id) ON DELETE CASCADE
);
```

## Acciones al borrar el padre

| `ON DELETE` | Efecto |
|---|---|
| `CASCADE` | borra los hijos |
| `RESTRICT` | impide borrar al padre si hay hijos (por defecto) |
| `SET NULL` | el FK del hijo pasa a NULL (la columna debe ser nullable) |

## Many-to-many

```sql
CREATE TABLE task_tags (
    task_id bigint NOT NULL REFERENCES tasks (id) ON DELETE CASCADE,
    tag_id bigint NOT NULL REFERENCES tags (id) ON DELETE CASCADE,
    PRIMARY KEY (task_id, tag_id)
);
```

## Índices

La PK y las columnas `UNIQUE` ya tienen índice.

```sql
CREATE INDEX idx_tasks_status ON tasks (status);
CREATE INDEX idx_tasks_owner ON tasks (owner_id);
CREATE INDEX idx_tasks_title_lower ON tasks (lower(title));
```

Crea índice en columnas de `WHERE`, `JOIN` y `ORDER BY` cuando la tabla deje de ser diminuta. Un índice de más en una tabla de 10 filas no molesta en un ejercicio; explícalo igual.

## Ver el plan

```sql
EXPLAIN ANALYZE
SELECT * FROM tasks WHERE status = 'pending';
```

`Seq Scan` en una tabla pequeña es normal.

## Integridad que conviene declarar en SQL

```sql
ALTER TABLE tasks
    ADD CONSTRAINT tasks_status_chk
    CHECK (status IN ('pending', 'in_progress', 'done'));

ALTER TABLE tasks
    ALTER COLUMN title SET NOT NULL;
```

La validación de Symfony o Bean Validation no sustituye la restricción de la base: otro cliente puede saltársela.
