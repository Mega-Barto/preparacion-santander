# PostgreSQL — Tipos de datos

## Los que vas a usar

| Tipo | Cuándo | Ejemplo |
|---|---|---|
| `bigint` / `bigserial` | id autonumérico | `id bigint GENERATED ALWAYS AS IDENTITY` |
| `integer` | contadores pequeños | `priority integer` |
| `varchar(n)` | texto corto con límite | `title varchar(180)` |
| `text` | texto largo | `description text` |
| `boolean` | flags | `done boolean DEFAULT false` |
| `numeric(10,2)` | dinero | `price numeric(10,2)` |
| `date` | solo fecha | `due_on date` |
| `timestamptz` | instante con zona | `created_at timestamptz` |
| `jsonb` | documento flexible | `metadata jsonb` |
| `uuid` | id opaco | `id uuid DEFAULT gen_random_uuid()` |

Prefiere `timestamptz` a `timestamp`. Guarda en UTC y formatea en la aplicación.

## Identity (recomendado frente a serial)

```sql
id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

`BY DEFAULT` permite insertar un id explícito en un seed. `ALWAYS` lo impide salvo `OVERRIDING SYSTEM VALUE`.

## Booleanos

Los literales son `true` y `false`. También se aceptan `'t'` / `'f'`, pero no los uses en scripts nuevos.

## Texto

`varchar(n)` y `text` tienen el mismo rendimiento. Elige `varchar` cuando el límite es una regla de negocio (título de 180) y `text` cuando no hay tope.

## JSON

```sql
metadata jsonb NOT NULL DEFAULT '{}'::jsonb
SELECT metadata->>'priority' FROM tasks;
```

`->` devuelve JSON. `->>` devuelve texto.

## Enumerados

Para un ejercicio, una `varchar` con `CHECK` es más simple que un tipo `ENUM`:

```sql
status varchar(20) NOT NULL DEFAULT 'pending'
    CHECK (status IN ('pending', 'in_progress', 'done'))
```

Cambiar un `ENUM` de PostgreSQL en mitad de la prueba es lento. El `CHECK` se altera con un `ALTER TABLE`.
