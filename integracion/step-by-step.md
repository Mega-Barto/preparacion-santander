# Step-by-step — Task Manager (Symfony + Vue + React)

Cómo se construyó esta integración y en qué orden conviene leerla o recrearla desde cero.

```
PostgreSQL :5432
      ↑
Symfony :8000  →  /api/tasks  (GET · GET/{id} · POST · PUT · DELETE)
      ↑                    ↑
  Vue :5173          React :3000
```

Regla de oro: **el backend no sabe que existen frontends**. Devuelve JSON puro y deja que el navegador gestione la UI. Por eso los dos frontends funcionan a la vez contra el mismo servidor.

---

## Fase 1 — Base de datos

### 1.1 Crear la base de datos

```powershell
psql -U postgres -c "CREATE DATABASE tasks"
```

Si el usuario no es `postgres`, cámbialo en todos los comandos siguientes. Si la clave no es `postgres`, añade `-W` y escríbela cuando `psql` la pida.

### 1.2 Crear la tabla — `database/init.sql`

```sql
CREATE TABLE IF NOT EXISTS tasks (
    id          INT GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    title       VARCHAR(180) NOT NULL,
    description TEXT DEFAULT NULL,
    status      VARCHAR(20)  NOT NULL,
    created_at  TIMESTAMP(0) WITHOUT TIME ZONE NOT NULL,
    PRIMARY KEY (id)
);
```

Línea a línea:

| Columna | Tipo | Por qué así |
|---|---|---|
| `id` | `IDENTITY` | PostgreSQL genera el entero automáticamente; Doctrine lo lee con `IDENTITY` strategy |
| `title` | `VARCHAR(180) NOT NULL` | 180 = límite que define `#[Assert\Length(max: 180)]` en la entidad PHP |
| `description` | `TEXT DEFAULT NULL` | Nullable; no se exige al crear una tarea |
| `status` | `VARCHAR(20) NOT NULL` | Sin `DEFAULT`; lo pone Doctrine a través del constructor de la entidad |
| `created_at` | `TIMESTAMP(0) WITHOUT TIME ZONE NOT NULL` | Sin zona horaria; la app ya trabaja en UTC |

> `TIMESTAMP(0)` elimina los microsegundos. Doctrine almacena `DateTimeImmutable` con precisión de segundos.

### 1.3 Insertar datos de prueba — `database/seed.sql`

```sql
INSERT INTO tasks (title, description, status, created_at) VALUES
  ('Preparar el entorno',   'Comprobar php, node y psql',              'done',        '2026-11-10 08:00:00'),
  ('Modelar la entidad',    'id, title, description, status, createdAt','in_progress', '2026-11-10 08:15:00'),
  ('Exponer GET /api/tasks','Listado JSON ordenado por fecha',          'pending',     '2026-11-10 08:30:00'),

```

Cinco filas con los tres estados para comprobar de un vistazo que el frontend los muestra bien.

## Fase 2 — Entidad Doctrine

**Archivo:** `backend/src/Entity/Task.php`

### 2.1 Anotaciones de mapeo

```php
#[ORM\Entity(repositoryClass: TaskRepository::class)]
#[ORM\Table(name: 'tasks')]
class Task
```

- `repositoryClass` conecta la entidad con su repositorio. Doctrine inyecta el repositorio sin configuración extra.
- `name: 'tasks'` fuerza el nombre de tabla. Sin esto Doctrine usaría `task` (nombre de la clase en snake_case).

### 2.2 Campo id

```php
#[ORM\Id]
#[ORM\GeneratedValue(strategy: 'IDENTITY')]
#[ORM\Column]
private ?int $id = null;
```

- `strategy: 'IDENTITY'` le dice a Doctrine que el valor lo genera la BD con `IDENTITY` (el `nextval` de PostgreSQL).
- Es `?int` porque antes de persistir vale `null`; después de `flush()` ya tiene el id real.

### 2.3 Campo title con validación doble

```php
#[ORM\Column(length: 180)]
#[Assert\NotBlank]
#[Assert\Length(max: 180)]
private string $title = '';
```

- `#[Assert\NotBlank]` → falla si es cadena vacía o solo espacios.
- `#[Assert\Length(max: 180)]` → falla si supera 180 caracteres.
- El límite coincide con `VARCHAR(180)` en la tabla. Si el validador pasa, la BD no truncará.

### 2.4 Campo status con lista cerrada

```php
#[ORM\Column(length: 20)]
#[Assert\Choice(choices: ['pending', 'in_progress', 'done'])]
private string $status = 'pending';
```

- El valor por defecto `'pending'` lo asigna la propia propiedad PHP, **no** la BD.
- `Assert\Choice` devuelve 422 antes de llegar a la BD si se envía un valor no válido.

### 2.5 Campo createdAt autoinicializado

```php
#[ORM\Column]
private \DateTimeImmutable $createdAt;

public function __construct()
{
    $this->createdAt = new \DateTimeImmutable();
}
```

- El constructor rellena `createdAt` cuando se instancia la entidad con `new Task()`.
- `\DateTimeImmutable` garantiza que la fecha no cambie accidentalmente después de persistir.
- El controlador **no toca** este campo nunca.

## Fase 3 — Repository

**Archivo:** `backend/src/Repository/TaskRepository.php`

```php
class TaskRepository extends ServiceEntityRepository
{
    public function __construct(ManagerRegistry $registry)
    {
        parent::__construct($registry, Task::class);
    }
}
```

El repositorio no tiene métodos propios porque el CRUD básico está cubierto:

| Método heredado | Cuándo se usa en el controlador |
|---|---|
| `find($id)` | `show()`, `update()`, `delete()` |
| `findBy([], ['createdAt' => 'DESC'])` | `list()` — ordena por fecha descendente |
| `findAll()` | No se usa; `findBy` es más flexible |

Si en el futuro se necesitase filtrar por estado, se añadiría aquí un `findByStatus(string $status)` con QueryBuilder.

## Fase 4 — Controlador API

**Archivo:** `backend/src/Controller/TaskApiController.php`

### 4.1 Inyección de dependencias en el constructor

```php
public function __construct(
    private TaskRepository $tasks,
    private EntityManagerInterface $em,
    private ValidatorInterface $validator,
) {}
```

Symfony inyecta automáticamente los tres servicios. No hace falta `@Autowire` explícito.

### 4.2 GET /api/tasks — listar

```php
#[Route('', name: 'api_task_list', methods: ['GET'])]
public function list(): Response
{
    $data = array_map(
        [$this, 'toArray'],
        $this->tasks->findBy([], ['createdAt' => 'DESC'])
    );
    return $this->json($data);
}
```

- `findBy([], ['createdAt' => 'DESC'])` devuelve todas las tareas ordenadas de más reciente a más antigua.
- `array_map([$this, 'toArray'], ...)` convierte cada entidad en array plano antes de serializar.

### 4.3 GET /api/tasks/{id} — detalle

```php
#[Route('/{id}', name: 'api_task_show', requirements: ['id' => '\d+'], methods: ['GET'])]
public function show(int $id): Response
{
    $task = $this->tasks->find($id);
    if (!$task) {
        return $this->json(['error' => 'Task not found'], Response::HTTP_NOT_FOUND);
    }
    return $this->json($this->toArray($task));
}
```

- `requirements: ['id' => '\d+']` evita que rutas como `/api/tasks/abc` lleguen a este método.
- 404 explícito con mensaje legible para el frontend.

### 4.4 POST /api/tasks — crear

```php
#[Route('', name: 'api_task_create', methods: ['POST'])]
public function create(Request $request): Response
{
    $payload = json_decode($request->getContent(), true);
    if (!is_array($payload)) {
        return $this->json(['error' => 'Invalid JSON'], Response::HTTP_BAD_REQUEST);
    }

    $task = new Task();
    $task->setTitle((string) ($payload['title'] ?? ''));
    $task->setDescription($payload['description'] ?? null);
    if (!empty($payload['status'])) {
        $task->setStatus((string) $payload['status']);
    }

    $errors = $this->validator->validate($task);
    if (count($errors) > 0) {
        return $this->json(['errors' => (string) $errors], Response::HTTP_UNPROCESSABLE_ENTITY);
    }

    $this->em->persist($task);
    $this->em->flush();

    return $this->json($this->toArray($task), Response::HTTP_CREATED);
}
```

**Ciclo completo de una creación:**

```
1. json_decode()       → array PHP del cuerpo de la petición
2. new Task()          → entidad con createdAt ya inicializado
3. setTitle/Status...  → hidratar campos desde el payload
4. validate()          → Assert\NotBlank, Assert\Choice, Assert\Length
5. persist()           → marca la entidad para INSERT
6. flush()             → ejecuta el INSERT en PostgreSQL, rellena $id
7. json(toArray, 201)  → responde con el objeto completo (incluido el id nuevo)
```

> Si `status` no viene en el payload, se mantiene `'pending'` (el default del constructor).

### 4.5 PUT /api/tasks/{id} — actualizar

```php
#[Route('/{id}', name: 'api_task_update', requirements: ['id' => '\d+'], methods: ['PUT'])]
public function update(int $id, Request $request): Response
{
    $task = $this->tasks->find($id);
    if (!$task) {
        return $this->json(['error' => 'Task not found'], Response::HTTP_NOT_FOUND);
    }

    $payload = json_decode($request->getContent(), true);

    if (array_key_exists('title', $payload))       { $task->setTitle((string) $payload['title']); }
    if (array_key_exists('description', $payload)) { $task->setDescription($payload['description']); }
    if (array_key_exists('status', $payload))      { $task->setStatus((string) $payload['status']); }

    $errors = $this->validator->validate($task);
    if (count($errors) > 0) {
        return $this->json(['errors' => (string) $errors], 422);
    }

    $this->em->flush();   // persist() no es necesario; la entidad ya está tracked

    return $this->json($this->toArray($task));
}
```

- `array_key_exists` permite actualización parcial: si solo envías `{"status":"done"}`, `title` no se toca.
- **No se llama a `persist()`** porque la entidad ya la conoce el EntityManager (la cargó `find()`).

### 4.6 DELETE /api/tasks/{id}

```php
#[Route('/{id}', name: 'api_task_delete', requirements: ['id' => '\d+'], methods: ['DELETE'])]
public function delete(int $id): Response
{
    $task = $this->tasks->find($id);
    if (!$task) {
        return $this->json(['error' => 'Task not found'], Response::HTTP_NOT_FOUND);
    }
    $this->em->remove($task);
    $this->em->flush();
    return new Response('', Response::HTTP_NO_CONTENT);
}
```

- 204 No Content: cuerpo vacío, sin JSON. El frontend no intenta parsear nada.

### 4.7 Método privado toArray()

```php
private function toArray(Task $task): array
{
    return [
        'id'          => $task->getId(),
        'title'       => $task->getTitle(),
        'description' => $task->getDescription(),
        'status'      => $task->getStatus(),
        'createdAt'   => $task->getCreatedAt()->format(\DateTimeInterface::ATOM),
    ];
}
```

- Controla exactamente qué se expone. Si la entidad tuviera un campo `passwordHash`, no aparecería aquí.
- `ATOM` = `Y-m-d\TH:i:sP` (ISO 8601 con zona horaria). JavaScript lo parsea directamente con `new Date()`.

## Fase 5 — CORS

**Archivo:** `backend/config/packages/nelmio_cors.yaml`

```yaml
nelmio_cors:
    defaults:
        origin_regex: true
        allow_origin: ['^https?://(localhost|127\.0\.0\.1)(:[0-9]+)?$']
        allow_methods: ['GET', 'OPTIONS', 'POST', 'PUT', 'PATCH', 'DELETE']
        allow_headers: ['Content-Type', 'Authorization']
        max_age: 3600
    paths:
        '^/api/': ~
```

- `origin_regex: true` activa expresiones regulares en `allow_origin`.
- El patrón acepta cualquier puerto (`:[0-9]+`?) para no tener que cambiar la config si se mueve Vue o React.
- `paths: '^/api/': ~` limita CORS solo a rutas que empiecen por `/api/`. Las rutas no-API no envían cabeceras CORS.
- `max_age: 3600` indica al navegador que puede cachear la respuesta del preflight OPTIONS durante 1 hora.

**Por qué hace falta:** Vue corre en `:5173` y React en `:3000`. El navegador detecta que el origen es distinto al del backend (`:8000`) y bloquea la petición con un error de política del mismo origen. El bundle NelmioCors añade las cabeceras `Access-Control-Allow-*` necesarias.

### 7.3 Cliente HTTP — `src/api/client.js`

```js
import axios from 'axios'

const http = axios.create({
  baseURL: import.meta.env.VITE_API_URL || 'http://127.0.0.1:8000',
  headers: { 'Content-Type': 'application/json' }
})

function messageFrom(error) {
  const data = error.response?.data
  if (typeof data?.errors === 'string') return data.errors
  if (typeof data?.error  === 'string') return data.error
  return error.message || 'Error de red'
}

export const api = {
  async list()             { return (await http.get('/api/tasks')).data },
  async show(id)           { return (await http.get(`/api/tasks/${id}`)).data },
  async create(payload)    { return (await http.post('/api/tasks', payload)).data },
  async update(id, payload){ return (await http.put(`/api/tasks/${id}`, payload)).data },
  async remove(id)         { await http.delete(`/api/tasks/${id}`) },
  messageFrom
}
```

- La instancia `http` lleva `baseURL` y cabeceras preconfiguradas. Cada método solo define el verbo y la ruta relativa.
- `messageFrom` extrae el mensaje de error del JSON de Symfony (`errors` o `error`), o usa el mensaje de red.

### 7.4 Store Pinia — `src/stores/tasks.js`

```js
export const useTaskStore = defineStore('tasks', () => {
  const items   = ref([])
  const loading = ref(false)
  const error   = ref('')

  const pendingCount = computed(
    () => items.value.filter(t => t.status !== 'done').length
  )

  async function fetchAll() {
    loading.value = true
    error.value = ''
    try {
      items.value = await api.list()
    } catch (e) {
      error.value = api.messageFrom(e)
    } finally {
      loading.value = false
    }
  }

  async function create(payload) {
    const created = await api.create(payload)
    items.value.unshift(created)   // añadir al principio (orden descendente)
    return created
  }

  async function update(id, payload) {
    const updated = await api.update(id, payload)
    const index = items.value.findIndex(t => t.id === updated.id)
    if (index === -1) items.value.unshift(updated)
    else items.value[index] = updated   // reemplaza en su posición
    return updated
  }

  async function remove(id) {
    await api.remove(id)
    items.value = items.value.filter(t => t.id !== Number(id))
  }

  function find(id) {
    return items.value.find(t => t.id === Number(id)) || null
  }

  return { items, loading, error, pendingCount, fetchAll, create, update, remove, find }
})
```

**Por qué `Number(id)`:** los parámetros de ruta llegan como string desde la URL (`"/tasks/3"`). La comparación `3 === "3"` falla en JS; `Number("3") === 3` pasa.

### 7.5 Router — `src/router/index.js`

### 7.6 TaskList.vue

```vue
<script setup>
import { onMounted } from 'vue'
import { storeToRefs } from 'pinia'
import { useTaskStore } from '../stores/tasks'

const store = useTaskStore()
const { items, loading } = storeToRefs(store)  // items y loading son reactivos

onMounted(() => store.fetchAll())              // carga al montar el componente

async function remove(id) {
  try {
    await store.remove(id)
  } catch (e) {
    store.error = e.response?.data?.error || e.message
  }
}
</script>

<template>
  <p v-if="loading">Cargando…</p>
  <p v-else-if="items.length === 0">No hay tareas.</p>
  <table v-else>
    <tr v-for="task in items" :key="task.id">
      <td><RouterLink :to="{ name: 'task-detail', params: { id: task.id } }">{{ task.title }}</RouterLink></td>
      <td>{{ task.status }}</td>
      <td><button @click="remove(task.id)">Borrar</button></td>
    </tr>
  </table>
</template>
```

- `storeToRefs` es necesario para que `items` y `loading` mantengan la reactividad al desestructurar el store.
- Si se hiciera `const { items } = store` sin `storeToRefs`, la variable sería un valor estático no reactivo.

### 7.7 TaskForm.vue — formulario controlado con v-model

```vue
<script setup>
import { reactive, ref } from 'vue'
const form = reactive({ title: '', description: '', status: 'pending' })
const localError = ref('')

async function onSubmit() {
  localError.value = ''
  try {
    await store.create({ ...form })  // copia plana para no pasar el Proxy
    router.push({ name: 'tasks' })
  } catch (e) {
    localError.value = api.messageFrom(e)
  }
}
</script>

<template>
  <form @submit.prevent="onSubmit">
    <input v-model.trim="form.title" required maxlength="180" />
    <textarea v-model="form.description" />
    <select v-model="form.status">
      <option value="pending">Pendiente</option>
      <option value="in_progress">En curso</option>
      <option value="done">Hecha</option>
    </select>
    <button type="submit">Guardar</button>
  </form>
</template>
```

- `@submit.prevent` cancela el envío nativo del formulario y ejecuta `onSubmit()`.
- `v-model.trim` en el título elimina espacios al inicio y al final antes de guardar.
- `{ ...form }` spread el objeto reactivo a un POJO limpio antes de enviarlo al store.

### 7.8 TaskDetail.vue — cache + update de estado

```vue
async function load() {

  if (cached) {
    task.value = cached
    return
  }
  task.value = await api.show(props.id) // solo pide al servidor si no está en caché

async function saveStatus() {

```

Patrón: **cache-first**. Evita un GET innecesario si el usuario llegó desde el listado (donde el store ya tiene todos los ítems).

### 8.2 Servicio HTTP — `src/api/taskService.js`

```js
const baseURL = import.meta.env.VITE_API_URL || 'http://127.0.0.1:8000'

async function request(path, options = {}) {
  const response = await fetch(`${baseURL}${path}`, {
    headers: { 'Content-Type': 'application/json', ...(options.headers || {}) },
    ...options
  })

  if (response.status === 204) return null          // DELETE: cuerpo vacío

  const text = await response.text()
  const data = text ? JSON.parse(text) : null

  if (!response.ok) {
    const message = data?.errors || data?.error || `HTTP ${response.status}`
    throw new Error(typeof message === 'string' ? message : 'Request failed')
  }

  return data
}

export const list   = ()            => request('/api/tasks')
export const create = (payload)     => request('/api/tasks',      { method: 'POST',   body: JSON.stringify(payload) })
export const update = (id, payload) => request(`/api/tasks/${id}`,{ method: 'PUT',    body: JSON.stringify(payload) })
export const remove = (id)          => request(`/api/tasks/${id}`,{ method: 'DELETE' })
```

- `fetch` no lanza error en 4xx/5xx; hay que comprobar `response.ok` manualmente.
- `response.text()` primero (no `response.json()`) porque el 204 tiene cuerpo vacío y `JSON.parse('')` lanzaría error.

### 8.3 Context + Reducer — `src/state/TaskContext.jsx`

```jsx
export function taskReducer(state, action) {
  switch (action.type) {
    case 'loading': return { ...state, loading: true,  error: '' }
    case 'loaded':  return { ...state, loading: false, items: action.items }
    case 'created': return { ...state, items: [action.item, ...state.items] }
    case 'updated': return { ...state, items: state.items.map(t => t.id === action.item.id ? action.item : t) }
    case 'removed': return { ...state, items: state.items.filter(t => t.id !== action.id) }
    case 'failed':  return { ...state, loading: false, error: action.error }
    default:        return state
  }
}
```

- `useReducer` centraliza todas las transiciones de estado en un lugar predecible.
- Cada `case` devuelve un **objeto nuevo** (`{ ...state, ... }`); nunca muta el estado anterior.

```jsx
export function TaskProvider({ children }) {
  const [state, dispatch] = useReducer(taskReducer, initialState)

  async function fetchAll() {
    dispatch({ type: 'loading' })
    try {
      dispatch({ type: 'loaded', items: await taskService.list() })
    } catch (e) {
      dispatch({ type: 'failed', error: e.message })
    }
  }

  useEffect(() => { fetchAll() }, [])  // carga al montar el Provider

  return (
    <TaskContext.Provider value={{ ...state, fetchAll, create, update, remove }}>
      {children}
    </TaskContext.Provider>
  )
}
```

- `useEffect(fn, [])` con array vacío = "ejecutar una sola vez al montar". Equivale a `onMounted` de Vue.
- El Provider pone el estado y las acciones disponibles para **todo el árbol** de componentes que lo envuelva.

```jsx
export function useTasks() {
  const context = useContext(TaskContext)
  if (!context) throw new Error('useTasks debe usarse dentro de TaskProvider')
  return context
}
```

- El error explícito en `useTasks` avisa si alguien lo usa fuera del Provider.

### 8.4 TaskListPage.jsx

```jsx
export function TaskListPage() {
  const { items, loading, update, remove } = useTasks()

  async function changeStatus(task, status) {
    try { await update(task.id, { status }) }
    catch (e) { /* mostrar error */ }
  }

  if (loading && items.length === 0) return <p>Cargando…</p>

  return (
    <table>
      <tbody>
        {items.map(task => (
          <tr key={task.id}>
            <td>{task.title}</td>
            <td>
              <select value={task.status} onChange={e => changeStatus(task, e.target.value)}>
                <option value="pending">Pendiente</option>
                <option value="in_progress">En curso</option>
                <option value="done">Hecha</option>
              </select>
            </td>
            <td><button onClick={() => remove(task.id)}>Borrar</button></td>
          </tr>
        ))}
      </tbody>
    </table>
  )
}
```

- El `select` controlado (`value={task.status}`) con `onChange` que llama directamente a `update` es el patrón React equivalente al `v-model` + watcher de Vue.

### 8.5 TaskFormPage.jsx — formulario controlado

```jsx
export function TaskFormPage() {
  const { create } = useTasks()
  const navigate = useNavigate()
  const [form, setForm] = useState({ title: '', description: '', status: 'pending' })

  function updateField(event) {
    const { name, value } = event.target
    setForm(current => ({ ...current, [name]: value }))  // actualiza solo el campo tocado
  }

  async function handleSubmit(event) {
    event.preventDefault()
    try {
      await create(form)
      navigate('/tasks')    // equivale a router.push en Vue
    } catch (e) {
      setLocalError(e.message)
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="title" value={form.title} onChange={updateField} required maxLength={180} />
      <textarea name="description" value={form.description} onChange={updateField} />
      <select name="status" value={form.status} onChange={updateField}>...</select>
      <button type="submit">Guardar</button>
    </form>
  )
}
```

- `[name]: value` es "computed property name": actualiza la clave del objeto cuyo nombre es el atributo `name` del input.
- `event.preventDefault()` cancela el submit nativo del form.

### 8.6 App.jsx — rutas y layout

```jsx
export default function App() {
  const { items, error } = useTasks()
  const open = items.filter(t => t.status !== 'done').length

  return (
    <>
      <header>
        <nav>
          <NavLink to="/tasks">Tareas ({open} abiertas)</NavLink>
          <NavLink to="/tasks/new">Nueva</NavLink>
        </nav>
      </header>
      <main>
        {error ? <p className="error">{error}</p> : null}
        <Routes>
          <Route path="/"         element={<Navigate to="/tasks" replace />} />
          <Route path="/tasks"    element={<TaskListPage />} />
          <Route path="/tasks/new" element={<TaskFormPage />} />
          <Route path="*"         element={<p>No existe esta página.</p>} />
        </Routes>
      </main>
    </>
  )
}
```

- `<Navigate to="/tasks" replace />` redirige `/` a `/tasks` sin añadir entrada al historial del navegador.
- `<Route path="*">` es el fallback 404 para rutas inexistentes.

### 8.7 main.jsx — árbol de providers

```jsx
createRoot(document.getElementById('root')).render(
  <StrictMode>
    <BrowserRouter>
      <TaskProvider>
        <App />
      </TaskProvider>
    </BrowserRouter>
  </StrictMode>
)
```

**Orden de providers (de fuera a dentro):**

1. `StrictMode` — detecta efectos secundarios en desarrollo (monta componentes dos veces intencionalmente).
2. `BrowserRouter` — provee el contexto de enrutado a toda la app.
3. `TaskProvider` — provee el estado global de tareas.
4. `App` — el árbol de componentes visibles.

`App` puede usar `useTasks()` porque está dentro de `TaskProvider`, y puede usar `useNavigate()` porque está dentro de `BrowserRouter`.

## Fase 9 — Comparativa Vue ↔ React en el mismo CRUD

| Concepto | Vue | React |
|---|---|---|
| Estado global | `defineStore` (Pinia) | `createContext` + `useReducer` |
| Acceder al estado | `storeToRefs(store)` | `useTasks()` (hook) |
| Carga inicial | `onMounted(() => store.fetchAll())` | `useEffect(() => fetchAll(), [])` |
| Estado local del form | `reactive({ title: '' })` | `useState({ title: '' })` |
| Formulario 2-way | `v-model="form.title"` | `value={form.title} onChange={updateField}` |
| Renderizado condicional | `v-if` / `v-else-if` / `v-else` | `{cond ? <A/> : <B/>}` o `{cond && <A/>}` |
| Lista | `v-for="t in items" :key="t.id"` | `items.map(t => <tr key={t.id}>...)` |
| Evento de clic | `@click="fn(id)"` | `onClick={() => fn(id)}` |
| Navegación | `router.push({ name: 'tasks' })` | `navigate('/tasks')` |
| Parámetro de ruta | `props: true` + `defineProps({ id })` | `useParams().id` |
| Enlace activo | `<RouterLink>` (class `router-link-active`) | `<NavLink>` (class `active`) |
| Layout global | `<RouterView>` en `App.vue` | `<Routes>` en `App.jsx` |
| Punto de entrada | `createApp(App).use(pinia).use(router).mount()` | `createRoot().render(<BrowserRouter><Provider><App/>)` |
